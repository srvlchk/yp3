# Умный офис — прототип системы мониторинга и охлаждения
---


Согласно плану офиса (`офис.png`), датчики и исполнительные устройства распределены по зонам[cite: 3, 16]:
* **Серверная (`server_room`):** датчик температуры `TEMP-01` и вентилятор охлаждения `FAN-01`[cite: 3, 16].
* **Рабочая зона (`work_area`):** датчик влажности `HUM-01`[cite: 3, 16].
* **Коридор / стойка связи:** коммутатор, связывающий сегменты сети офиса[cite: 12, 16].

## Архитектура и роли узлов

Виртуальная инфраструктура собрана в **GNS3** на базе маршрутизатора Cisco RTR, коммутатора Cisco SW с разделением на три VLAN (маска `/26`), четырёх виртуальных машин на **РЕД ОС 8** и рабочей станции на **Windows Server 2019**[cite: 12, 15]:

| Узел | ОС / Платформа | Роль в системе | Основные сервисы и порты |
| :--- | :--- | :--- | :--- |
| **`WIN` (`WIN-01`)** | Windows Server 2019 | Рабочее место администратора и оператора[cite: 12, 15] | Доступ к веб-интерфейсам Node-RED (`1880`), Prometheus и Grafana[cite: 8, 9, 11] |
| **`IOT` (`IOT-01`)** | РЕД ОС 8 | Эмуляция IoT-датчиков и логики срабатывания вентилятора[cite: 8, 9, 12, 13, 15] | Docker Compose, Node-RED (`:1880`)[cite: 8, 9] |
| **`CTRL` (`CTRL-01`)** | РЕД ОС 8 | Управляющий узел и приёмник показаний / команд[cite: 8, 9, 11, 15] | Docker Compose, приёмник (`:8080`), `/api/readings`, `/api/actuators`, `/metrics`[cite: 3, 9, 11] |
| **`DB` (`DB-01`)** | РЕД ОС 8 | Хранение истории измерений и состояний вентилятора[cite: 8, 10, 15] | Docker Compose, API БД (`:8081`), SQLite (таблицы `measurements` и `FAN`) |
| **`MON` (`MON-01`)** | РЕД ОС 8 | Мониторинг, визуализация и алертинг[cite: 11, 12, 15] | Системные службы Prometheus и Grafana (без Docker Compose) |

## Как работает система

1. **Генерация данных (`IOT-01`):** в Node-RED каждые 5 секунд формируются показания температуры `TEMP-01` (в `°C`) и влажности `HUM-01` (в `%`) в формате JSON[cite: 3].
2. **Автоматическое управление (`IOT-01` -> `CTRL-01`):** блок `switch` проверяет значение `TEMP-01`[cite: 3]. Если температура превышает **30 °C**, формируется команда `FAN-01` со статусом `ON` (`mode: auto`); если температура 30 °C или ниже — команда `OFF`[cite: 3, 13].
3. **Приём и запись в БД (`CTRL-01` и `DB-01`):** показания датчиков и состояния вентилятора отправляются HTTP POST-запросами на `/api/readings` и `/api/actuators` приёмника `CTRL` (`:8080`) и сервиса базы данных `DB` (`:8081`), где сохраняются в SQLite[cite: 3, 10].
4. **Мониторинг и оповещения (`MON-01`):** Prometheus каждые 5 секунд опрашивает `http://<IP_CTRL>:8080/metrics` (`job="office-controller"`)[cite: 5, 6, 11]. Grafana отображает текущие показатели и графики, а правила оповещения отслеживают устаревание данных датчиков (`> 20s`) и доступность самого узла `CTRL`[cite: 5, 6, 11].

## Содержимое репозитория

* `офис.png` — план-схема офиса с размещением датчиков `TEMP`, `HUM`, вентилятора `FAN` и коммутатора.
* `flows.json` — начальный вариант узла сборки JSON-сообщения в Node-RED[cite: 2, 7].

* `office-10s .json` — экспорт правил оповещения Grafana (проверка каждые `10s` для `ctrl недоступен`, `TEMP-01`, `HUM-01`)[cite: 5, 7].
* `Задание №2.docx` – `Задание №7.docx` — отчёты по практическим работам с конфигурациями и скриншотами проверок[cite: 7, 8, 9, 10, 11, 12, 13].
* `journal.md` — рабочий журнал выполнения практики[cite: 7, 14].
* `CUSTOMER_GUIDE.md` — руководство пользователя / заказчика по работе с системой.
